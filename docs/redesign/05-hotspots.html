How to read Figure 5.1

  1. A hotspot is an intersection, not a sum. A cell is a hotspot when it is in the opportunity space and its need is at or above the chosen hotspot score.
  2. Need layers are proxies at 5 km. Correlated layers are grouped and one represents each group, so the same signal is not counted twice (Section 5.2).
  3. Residents are not beneficiaries. People counted in hotspot cells live there. Who would take part or benefit is a question for feasibility.
  4. The district view summarises. It shows where hotspots concentrate; it does not locate sites.

5.3How the score is built

Four steps from the opportunity space to hotspot classes.

Download PNG · unavailable in mock-up
  1. Opportunity space. Only cells in the suitability classes chosen in the control bar take part; everything else stays out.
  2. Need layers, one per cluster. Each objective brings a group of layers; correlated layers are clustered and one represents each cluster.
  3. Weighted combination. The representatives are standardised and combined with weights — here the example preset from Section 5.2.
  4. Hotspot classes. The combined score is cut into classes; the hotspot score in the control bar decides which classes count.

Figure 5.2 · How the hotspot score is built from the opportunity space and the need layers

Weights shown on this page are an example preset. The method combines expert weights with data-driven ones — a hybrid of AHP, CRITIC and entropy weighting — so no single judgement sets the result. No scoring runs in this prototype.
