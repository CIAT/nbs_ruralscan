## Sequence and acceptance

Use `split-sequence.csv` as the code-level decomposition within the existing execution board; it does not replace that board's dependencies. First introduce explicit build context and backwards-compatible wrappers **inside CIAT**, then cut minimal method reference/serialization interfaces, then evidence build/UI/submit boundaries. Prove full-corpus and accepted-baseline parity before new package publication or writer cutover.

The dependency direction must remain: **method definitions → evidence compiler → candidate artifact → method acceptance record → runtime pin**. Definitions and accepted analytical releases are separate immutable identities. Method documentation can embed a pinned evidence workbook artifact, but method's contract library must never import evidence or runtime production code. Runtime imports neither evidence review/ingestion nor mutable main. Avoid replacing a monorepo with a circular cross-repository build.

Do not block the evidence cutover on completed Haiti H2. Unchanged-pin diagnostic work can proceed independently; formal H1, H2 and public claims retain the board's acceptance gates. Runtime publisher adaptation, v0.1.7 adoption, environment/Colab bootstrap, and H2 gate implementation are separate reviews so changes remain attributable.

Dependency split: `dependency-ownership.csv` records 32 declared/observed dependency entries. Method validation/serialization can stay standard-library only; numerical reference tests need an explicit NumPy extra. CIAT currently imports NumPy directly but receives it transitively through the large geo stack—declare it where needed when that stack moves. Evidence PDF/web intake keeps its own optional ingestion dependencies. Runtime retains its separate geo/GEE/viz extras and gains a tested environment lock in M18. Never copy the CIAT lock wholesale into runtime.

Required migration checks: source tree hash; old CLI compatibility; full corpus rebuild before filtering; semantic diff against pinned accepted recipe; generated workbook counts/IDs; same reference conformance fixtures in runtime; no cross-repository import cycle; all-writer and reviewer replay/rollback rehearsal; clean independent notebook environment; honest unknown/excluded/scored spatial outputs. Existing test pointers are in the function schedule. Their presence is not a claim that tests were run here.
